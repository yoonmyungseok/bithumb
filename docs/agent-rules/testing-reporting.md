# 구현·검증·보고 규칙

## 책임 범위

이 문서는 코드 주석, 테스트 실행, 문서 갱신, diff 검사와 최종 보고의 단일 규칙 원본이다.

## 구현 기준

- 코드에는 의도, 안전 조건, 예외 처리, 유지보수 이유를 설명하는 한국어 주석을 작성한다. 자명한 동작을 반복하는 주석은 피한다.
- 기능 변경에는 변경 범위에 맞는 단위 또는 회귀 테스트를 추가하거나 갱신한다.
- 기존 사용자 변경과 무관한 파일을 되돌리거나 삭제하지 않는다.

## 검증 절차

- 관련된 좁은 테스트부터 실행하고, 변경 범위가 넓으면 연결된 회귀 테스트를 추가 실행한다.
- Python 테스트는 프로젝트 가상환경과 `PYTHONPATH=src`를 사용한다. 예: `$env:PYTHONPATH='src'; .\venv\Scripts\python.exe -m unittest discover -s tests -p 'test_order_safety.py' -v`
- Windows 임시 폴더 ACL 오류는 코드 실패와 분리해 정확히 보고한다.
- 구현 후 `git diff --check`를 실행한다.

## 최종 보고

- 변경 파일, 실제 안전 영향, 실행한 검증 명령과 성공·실패 결과를 우선 보고한다.
- 남은 불확실성은 확인된 사실과 구분해 명시한다.
- 코드 제안이나 보고에서 전체 파일을 반복하지 않고 필요한 변경 블록 또는 파일 링크를 사용한다.
