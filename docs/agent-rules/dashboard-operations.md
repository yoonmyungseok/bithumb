# 대시보드·운영 분석 규칙

## 책임 범위

이 문서는 운영 대시보드, UI 표시, 로그 노출, 상태 분석과 운영 보고의 단일 규칙 원본이다.

## 표시와 데이터 경계

- 표시 전용 변경은 UI 렌더링 경계에서 처리한다. 내부 주문 코드, DB 값, API 계약은 보존하고 사용자 표시 문자열만 한국어로 변환한다.
- 거래소별 탭은 해당 거래소 데이터만 보여야 하며, `combined` 화면에서만 두 거래소를 집계할 수 있다.
- 이상 로그는 기본적으로 `WARNING` 이상만 노출한다.
- 로그는 허용된 파일만 읽고, 자격 증명 값은 마스킹하며, 외부 문자열은 안전한 텍스트로 렌더링한다.

## 운영 분석과 보고

- 운영 상태는 소스, 로그, 저장 상태, REST·Private WebSocket 체결 기록을 구분해 근거와 함께 제시한다.
- 전송 타임아웃이나 WebSocket 종료만으로 인증 실패, 주문 실패, 체결 실패라고 단정하지 않는다.
- Public 시세 스트림 복구는 Private 주문·체결 스트림의 정상성을 증명하지 않는다. 필요하면 재구독과 REST 대사 결과를 함께 확인한다.
- 불확실한 대사·데이터 상태에서는 신규 BUY 차단 여부와 기존 포지션 보호 상태를 분리해 보고한다.
