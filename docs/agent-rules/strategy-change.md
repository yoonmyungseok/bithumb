# 전략·AI 판단 변경 규칙

## 책임 범위

이 문서는 진입, 청산, 필터, 임계값, 비중, 레짐, 세션, 후보 경로, AI 판단과 프롬프트 변경의 단일 규칙 원본이다.

## 변경 전 확인

- 전략·리스크 변경 전에는 대상 코드, 호출자, 관련 테스트, 환경 설정과 [전략 및 리스크 설계](../project-design/strategy-and-risk.md), `PROJECT_DESIGN.md` 인덱스를 확인한다.
- 실거래와 백테스트가 `StrategyPolicy` 등 같은 기준을 공유하는지 확인한다.
- 확정되지 않은 캔들이나 소프트 알파 점수로 하드 안전 게이트를 우회하지 않는다.
- 대규모 리팩터링이나 전략 변경은 영향 범위와 구현 계획을 먼저 제시하고 승인 후 진행한다.

## AI 지침 동기화

- 전략의 추가·수정·삭제 시 `src/gemini_analyzer.py`의 AI 매수 분석 프롬프트와 `BithumbGeminiProvider.SYSTEM_INSTRUCTION`을 같은 변경에서 갱신한다.
- 빗썸과 업비트의 프롬프트·모델 지침은 레짐, 세션, 후보 경로, 승인 기준, 안전 차단 조건, JSON 응답 스키마, Provider 격리와 일치해야 한다.
- 모든 Gemini 모델 지침에는 분석 보조, 거래소 데이터 격리, 제공된 데이터만 사용, ACK 비체결, 불확실한 신규 BUY 금지, 비밀정보 비출력 원칙을 포함한다.

## 필수 산출물

- 전략·안전 정책·데이터 흐름·운영 절차가 바뀌면 관련 `docs/project-design/` 설계 문서와 `changelog.md`를 갱신하고, 문서 책임이 바뀐 경우 `PROJECT_DESIGN.md` 인덱스도 갱신한다.
- 같은 변경에서 프롬프트 회귀 테스트와 관련 단위 또는 회귀 테스트를 추가·갱신한다.
- 공유 전략 함수를 바꾸기 전에는 빗썸과 업비트 각각의 영향을 확인하고 보고한다.
