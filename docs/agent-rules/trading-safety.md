# 주문·체결 안전 규칙

## 책임 범위

이 문서는 주문 제출, 주문 저널, 체결 처리, 잔고, REST 대사, Private WebSocket, Public WebSocket, 재조정, 손익, 쿨다운, 킬스위치 변경의 단일 규칙 원본이다.

## 확정 체결 원칙

- 주문 ACK, `OPEN`, `PARTIALLY_FILLED`, Private WebSocket 주문 이벤트는 체결 확정이 아니다.
- REST 주문 대사에서 체결 수량, 잔량, 평균 체결가와 수수료를 검증한 뒤에만 포지션, 손익, 쿨다운, 거래 메모리를 갱신한다.
- 확정 체결 누적값의 증가분만 반영해 재시도와 중복 이벤트가 상태를 두 번 변경하지 않게 한다.
- `identifier`와 주문 저널을 유지해 멱등성을 보장한다. 봇 소유가 아닌 주문을 취소·정정·정리하지 않는다.

## Fail-closed 기준

- 주문·체결·잔고·시세·호가·재조정 상태 중 하나라도 불확실하면 신규 BUY를 차단한다.
- `RECONCILIATION_PENDING`이거나 REST 대사가 미완료, 실패 또는 모순되면 신규 BUY를 막고 기존 포지션의 손절·익절·보호 관리만 유지한다.
- 0 이하 가격, 데이터 조회 실패, 스프레드 또는 호가 잔량 검증 실패, 미해결 주문, 쿨다운 차단도 신규 BUY 차단 사유다.
- 수동 관리 종목과 명시적 제외 종목, 특히 `KRW-HOLO`는 자동 매매, 긴급 매도, 자동 평가와 대시보드 자동 경로에서 제외한다.

## 실시간 연결과 상태 영속화

- WebSocket 콜백은 가볍게 유지하고 bounded queue에 넣은 뒤 메인 처리 경로에서 소비한다.
- 콜백 지연만으로 연결 끊김이나 이벤트 유실을 단정하지 않는다. 연결 종료 시 재연결·재구독과 REST 주문 대사를 확인한다.
- 상태 파일의 원자 저장과 백업 복구 규칙을 훼손하지 않는다. 주문 의도, 확정 체결, 청산, 킬스위치는 즉시 안전하게 영속화한다.
- 호가 단위 보정은 기존 방향별 계약을 지킨다. 매수는 과도한 가격 상승을 피하고 매도는 과도한 가격 하락을 피한다.
